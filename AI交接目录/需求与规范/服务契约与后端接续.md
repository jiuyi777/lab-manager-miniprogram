# 服务契约与后端接续

当前入口：软件/miniprogram/services/index.js。provider为local-demo；当前所有方法同步返回、同步抛Error。页面通过shared/view调用，禁止绕过服务去碰存储。

| 方法 | 输入 | 输出/作用 |
| --- | --- | --- |
| demoUsers | 无 | 演示账号列表；仅本地模式 |
| login | 演示用户id | 当前用户；不是真实认证 |
| logout | 无 | 清除当前演示会话，保留业务记录 |
| snapshot | 无 | 当前用户可见的实验室、仪器、本人预约、可审批记录、脱敏占位、试剂、本人样品、通知与管理员日志 |
| createBooking | requestId, instrumentId, start/end(YYYY-MM-DD HH:mm), purpose, sampleId可选 | 创建后的预约，含id/status/version |
| bookingAction | id, approve/reject/cancel/checkin/finish/return, version及reason | 状态变更后的预约 |
| consume | id, quantity整瓶正整数, purpose, requestId, sampleId可选 | 库存流水，含before/after |
| saveSample | name, composition, process, tests数组 | 生成编号后的本人样品 |
| readNotice | 本人通知id | 持久化已读 |

## 接真实后端前必须调整

1. HTTP是异步，不能照原始需求声称“只换API文件、页面零改动”。把接口统一改为Promise，同时让页面onShow、submit、shared/view.refresh/act显式await，处理loading、请求失败、旧请求覆盖及离页回调。
2. 当前snapshot是本机聚合方便原型；后端需分页接口，不能一次拉取全库或让客户端过滤保密信息。
3. 生产登录使用服务端校验学号/工号与密码；角色由服务端返回，不能接受客户端自报角色。不得把demoUsers/login(id)上线。
4. 后端重新执行所有权限和状态规则；部署数据库事务保护跨记录时段冲突、库存扣减与流水。JWT/refresh和撤销、WSS鉴权、通知可靠性也需落实。
5. 幂等key按用户和操作隔离，正式后端还应校验同key请求内容一致、设计保留期。当前本机示例仅复用第一次结果。
6. 业务时间采用Asia/Shanghai、严格校验输入，服务端时钟为准。当前本机时钟可被改动，不能用于正式签到凭证。
7. 文件上传需数据库归属、体积/类型校验及授权下载；不能仅保存公共URL替代权限。
8. 当前异常是中文Error，正式API定义稳定错误码，并将冲突、过期、权限撤销分别呈现；网络失败保留表单。

对照原始HTML中的接口清单补齐接口，但以NEXT和实现矩阵判断真实进度。不要创建第二套预约状态枚举；前后端契约需一起维护。
