# 给接手 AI 的项目规则

1. 先读 README.md → NEXT.md → 需求与规范/架构与拆分.md → 本次功能目录 README。不要从零重建，不要重做已定视觉。
2. 用户已确认：按“教室配置＋功能模块”拆分。501、502 各自配置；预约、权限、试剂、样品、日志分别实现，共用业务不能按教室复制。
3. **必须拆分，禁止屎山代码。** 不允许一个 app.js、index.js 或万能页面容纳所有业务；不允许用巨型 switch 拼完全部36页。
4. 页面仅负责交互和展示；模块负责业务；services 负责调用边界；data 负责存储。禁止页面直接改库存、审批状态或跨模块读写存储。
5. 单个源码文件超过300行先按职责拆分（检查脚本会报错）；不要为了凑行数压缩代码。也不为简单功能增加无消费者的抽象层。
6. 新教室只加 classrooms/<编号>/ 配置并登记索引。仪器清单、开放时间、功能开关由配置驱动，不复制预约页。
7. 权限在业务/后端校验，隐藏按钮不算鉴权。生产模式禁止保留任意切换管理员的演示登录。
8. 已定视觉：白色为主、黑色略带灰绿、少量浅绿与奶黄，细描边、轻微新拟物。以功能模块下设计图为参考；不能改回全黑或蓝色大渐变。
9. 默认隐藏所有滚动条外观并保留滚动。中文字体遵守需求与规范/视觉规范.md；当前代码默认字体是待替换的原型状态。
10. 修复须追到共同源头、关联页面、保存与下次使用；不要只修截图或只改一份生成物。
11. 进度只更新 NEXT.md。各功能 README 的实现状态随代码同步，避免相互矛盾。
12. 每次修改跑软件目录 npm test、npm run check。真实微信编译、真机、服务端联调与本地测试分开记录。
13. 首版是本地演示；不得说成线上多管理员实时系统。没有真实后端时不得伪造登录/同步成功。
14. 不删除原图、原始需求或用户文件，不自动安装、发布、部署或提交 Git。
15. 汇报用简短中文，直接说改动、测试和必要待办。用户称呼你“奶龙”。
